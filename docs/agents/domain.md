# Domain docs

Before domain-related work, read the root `GLOSSARY.md` and any relevant
decisions in `docs/adr/`. If they do not exist, proceed without them.

This repository uses a single domain context. The domain-modeling skill
creates the glossary and ADRs when needed.

Use the glossary's terms in issues, proposals, tests, and other output.
If a needed term is missing, note it for domain modeling. If a proposal
conflicts with an ADR, state the conflict explicitly.
